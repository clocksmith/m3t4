# ZK circuit build

This directory holds verification artifacts for L3 proof-carrying tier.
Server loads `vkey.json` at boot and registers the `snarkjs-groth16`
verifier. No vkey → the route rejects proofs with "no verifier
registered".

## Why this is a separate build step

The server uses real `snarkjs.groth16.verify()` — no mocks. But
producing the verification key requires the `circom` compiler (a Rust
binary) and a trusted-setup ceremony, neither of which run inside the
server TypeScript build. Production deployments run this once per
circuit revision and commit the resulting `vkey.json`.

## Prerequisites

```bash
# Install circom (requires Rust)
git clone https://github.com/iden3/circom.git
cd circom && cargo build --release
# Put `circom` on PATH.

# Install snarkjs CLI (already a server dependency but exposed as bin)
npm install -g snarkjs
```

## Build steps

```bash
# 1. Write circuit at server/zk/circuit.circom
#
#    Example minimal circuit: know preimage of a SHA-256 commitment.
#    For a real m3t4 L3, the circuit would encode:
#      - config is a 12-element fixed-point vector
#      - sum(|config_i|) ≤ 360 (budget legality)
#      - hash(config || salt) == public_commitment
#      - (advanced) action stream matches approved_brain(obs, config)
#
# 2. Compile to r1cs + wasm + sym
circom circuit.circom --r1cs --wasm --sym -o .

# 3. Powers-of-tau ceremony (one-time, reusable across circuits of the
#    same size bound). Use an existing one from a public ceremony if
#    possible — e.g. https://github.com/iden3/snarkjs/#7-prepare-phase-2
snarkjs powersoftau new bn128 12 pot12_0000.ptau -v
snarkjs powersoftau contribute pot12_0000.ptau pot12_0001.ptau --name="first" -v
snarkjs powersoftau prepare phase2 pot12_0001.ptau pot12_final.ptau -v

# 4. Circuit-specific zkey
snarkjs groth16 setup circuit.r1cs pot12_final.ptau circuit_0000.zkey
snarkjs zkey contribute circuit_0000.zkey circuit_final.zkey --name="first" -v

# 5. Export verification key
snarkjs zkey export verificationkey circuit_final.zkey vkey.json
```

## After the build

- Commit `server/zk/vkey.json` to the repo (it's a verification key,
  safe to publish).
- `circuit_final.zkey` + `circuit_js/circuit.wasm` go to the **prover**
  side (client or separate prover service). These are what generate
  proofs.
- Server boot should log: `[zk] loaded Groth16 vkey (curve=bn128, nPublic=N)`.
- Submit a real proof via `POST /api/proof/zk/submit` with:
  - `proofSystem: "snarkjs-groth16"`
  - `proofBytesB64`: base64 of JSON-encoded `{pi_a, pi_b, pi_c}` from
    snarkjs `groth16.prove`
  - `publicInputs`: array of field elements matching the circuit's
    public signals (commitment, budget bound, etc)

## What's NOT in this build

The full brain-v3 state machine in circuit form is deferred. The
circuit here would only prove **config legality under commitment**
(L1 + L3 hybrid: prove the committed config is budget-legal without
revealing it). Full L3 (prove the action log was generated by the
approved brain from a hidden legal config) is multi-week engineering:
re-express the stateful 5-mode brain as constraints, add fixed-point
arithmetic for every float operation, encode rolling opp-model
buffers as arrays. Out of scope until private-config ranked is a
confirmed product promise.
